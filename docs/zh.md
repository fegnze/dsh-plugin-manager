# dsh-plugin-manager

[English](../README.md) | 简体中文

在 DSH 官方插件页面内新增只读的「**管理**」页签，便于查找已安装 bundle，不替换原生管理器、不修改它的 DOM。

## 功能

- 搜索名称、描述、多语言元数据与插件模块名；空白分隔的多个关键词必须同时匹配，可跨语言搜索。
- 独立组合来源（官方／第三方）、状态（启用／停用／异常）及用途筛选。
- 官方风格圆角列表行，展示元数据图标、标题与描述层级、包名、版本、来源、推断用途与状态；鼠标或键盘激活整行打开官方详情。
- 「管理」位于「已安装」与「发现」之间。
- 手动刷新，并在官方插件管理操作后刷新。
- 中文／英文 UI 随宿主语言切换，使用宿主主题。

仅列出已安装 bundle。安装与运行事实全部来自官方 `pluginManager.listBundles()` 与 `listPlugins()`。bundle 出错或关联插件 fiber 失败时标记异常；「启用」指 bundle 被选中，不代表其每个插件均已运行。用途按本地关键词规则推断，包含开发工具、界面外观、效率工具、模型服务、MCP 集成、知识记忆与其他，仅为展示辅助，不冒充官方分类、不建立第二份注册表。

## 安装与使用

本地执行 `npm run build`，然后通过 DSH 官方安装器将本工程目录安装到 **desktop** profile。打开「插件 → 管理」，输入关键词并组合三个筛选器；「清除筛选」恢复列表。激活列表行打开该 bundle 的官方详情页，继续配置与管理。

npm 身份为 `@fegnze/dsh-plugin-manager`，本地目录与 GitHub 仓库使用短名 `dsh-plugin-manager`。不要安装无 scope 的第三方同名包。迁移旧本地安装时，先经官方管理器移除旧 bundle，再安装 scoped 包，不能同时加载两者。发布状态须独立核验，不以 manifest 元数据为证据。

## 权限与限制

Host 无运行副作用：不注册 HTTP 路由、子进程、定时器、工具或持久存储。Client 仅读取官方清单、注册 locale／Slot 资源，并在视图挂载期间订阅变更；卸载后的请求结果被忽略，插件卸载会清理所属资源。

无安装、卸载、启停、更新、配置写入或版本豁免控件，请在官方详情页执行这些操作。不假设存在专用更新 API。查询失败会明确报错，不伪装成空清单；可刷新重试。绕过官方管理器产生的变化可能需要手动刷新。

兼容声明限定 DSH `0.2.0-rc.2` 或 `0.2.1-rc.2`；升级后应重新核对运行契约。本地测试或 Slot 注册不代表真实 desktop 视觉验收通过。

## 开发

需要 Node 22+，无第三方构建／运行依赖安装，React 由 DSH 提供。`npm test` 先将 Client 模板与清单模型构建为 ModuleLoader 产物，再运行 Node 原生测试。构建产物不入 Git、但进入包；安装或打包前必须构建。

```sh
npm test
npm pack --dry-run --ignore-scripts
```

开发交付遵循工作区 plugin devkit 与原生 OpenSpec OPSX，源码同步和 npm 发布须分别核验。本地测试通过不代表已发布。
